目前，环境字典 `fabric.state.env` 是作为全局的单例实现的，为方便使用也包含在 `fabric.api` 中。 `env` 中的键通常也被称为“环境变量”。

## 运行环境即设置[¶](#environment-as-configuration "永久链接至标题")

Fabric 的大部分行为可以通过修改 `env` 变量，例如 `env.hosts` ,来控制（已经在 入门导览 中见过）。其他经常需要修改的环境变量包括：

-   `user` ：Fabric 在建立 SSH 连接时默认使用本地用户名，必要情况下可以通过修改 `env.user` 来设置。 [_Execution model_](https://fabric-chs.readthedocs.io/zh-cn/chs/usage/execution.html) 文档中还介绍了如何为每个主机单独设置用户名。
    
-   `password` ：用来显式设置默认连接或者在需要的时候提供 sudo 密码。如果没有设置密码或密码错误，Fabric 将会提示你输入。
    
-   `warn_only`：布尔值，用来设置 Fabric 是否在检测到远程错误时退出。访问 [_Execution model_](https://fabric-chs.readthedocs.io/zh-cn/chs/usage/execution.html) 以了解更多关于此行为的信息。
    

除了这些以外还有很多其它环境变量， [环境变量完整列表](#env-vars) 文档的底部提供了完整的列表。

### [`settings`](https://fabric-chs.readthedocs.io/zh-cn/chs/api/core/context_managers.html#fabric.context_managers.settings "fabric.context_managers.settings") 会话管理器[¶](#the-settings-context-manager "永久链接至标题")

很多时候，只需要临时修改 `env` 变量来修改指定设置很有必要。Fabric 提供了会话管理器 [`settings`](https://fabric-chs.readthedocs.io/zh-cn/chs/api/core/context_managers.html#fabric.context_managers.settings "fabric.context_managers.settings") 上下文管理器，接受一个或多个键/值对参数，用于修改其代码块内部的 `env` 。

在下面的几种情况下 `warn_only` 设置非常有必要。需要设置环境变量应用的范围，你可以参照下面 `contrib` [`exists`](https://fabric-chs.readthedocs.io/zh-cn/chs/api/contrib/files.html#fabric.contrib.files.exists "fabric.contrib.files.exists") 函数的简化版，使用 `settings(warn_only=True)` 。

from fabric.api import settings, run

def exists(path):
    with settings(warn\_only\=True):
        return run('test -e %s' % path)

查看 [_上下文管理器_](https://fabric-chs.readthedocs.io/zh-cn/chs/api/core/context_managers.html) API 文档以了解关于 [`settings`](https://fabric-chs.readthedocs.io/zh-cn/chs/api/core/context_managers.html#fabric.context_managers.settings "fabric.context_managers.settings") 和其它类似工具的细节。

## 其他考虑[¶](#other-considerations "永久链接至标题")

`env` 虽然是 `dict` 的子类，但它也做了些修改，以支持属性访问的方式进行读/写，这在前面也有所体现。换句话说， `.host_string` 和 `env['host_string']` 的作用是完全一样的。我们感觉属性访问通常可以少打一些打字，同时能增强代码的可读性，所以这也是推荐的与 env 交互的方式。

作为字典在其他方面也很有用，例如，需要往字符串中插入多个环境变量时，通过 Python 基于 dict 的字符串格式化显得尤其方便。“普通”的字符串格式化是这样的：

print("Executing on %s as %s" % (env.host, env.user))

使用字典格式化字符串更加简短，可读性也更好：

print("Executing on %(host)s as %(user)s" % env)

## 环境变量完整列表[¶](#full-list-of-env-vars "永久链接至标题")

需注意的是它们中的大部分可以通过 fab 的命令行参数来设置，详细文档参见 [_fab 选项和参数_](https://fabric-chs.readthedocs.io/zh-cn/chs/usage/fab.html) 。合适的时候也可以使用交叉引用。

### `abort_exception`[¶](#abort-exception "永久链接至标题")

**Default:** `None`

通常情况下，Fabric 处理错误的方式是先打印错误信息至 stderr，然后调用 sys.exit(1)。这项设置提供覆盖这个默认行为（即设置 `env.abort_exception` 为 `None` ）。

它接受一个接受单个字符串变量（需要打印的错误信息）的可调用对象，并返回一个异常实例。这样 Fabric 就会抛出该异常，而非 `退出系统` （如 `sys.exit` 所做）

大部分情况下，你可以简单地将它设置为一个异常类，因为它完美地符合了上面的要求（可调用、接受一个字符串、返回一个异常实例）。例如： `env.abort_exception = MyExceptionClass` 。

### `abort_on_prompts`[¶](#abort-on-prompts "永久链接至标题")

**Default:** `False`

当这个值为 `True` 时，Fabric 将以非交互模式运行。此模式下，任何需要提示用户输入（如提示输入密码、询问连接到哪个主机、fabfile 中触发的 [`prompt`](https://fabric-chs.readthedocs.io/zh-cn/chs/api/core/operations.html#fabric.operations.prompt "fabric.operations.prompt") 等等）时，都会调用 [`abort`](https://fabric-chs.readthedocs.io/zh-cn/chs/api/core/utils.html#fabric.utils.abort "fabric.utils.abort") 。这就保证 Fabric 会话总是明确地中止，而不是在某些意外的情况下傻傻地等待用户输入。

1.6 新版功能.

### `sudo_prefix`[¶](#sudo-prefix "永久链接至标题")

**Default:** `"sudo -S -p '%(sudo_prompt)s' " % env`

[`sudo`](https://fabric-chs.readthedocs.io/zh-cn/chs/api/core/operations.html#fabric.operations.sudo "fabric.operations.sudo") 命令调用时的 `sudo` 命令前缀。如果用户在远程主机默认 `$PATH``上没有 ``sudo`，或者需要一些其它设置时（比如应用无密码的 sudo 时删除 `-p` 参数），会需要它。

### `sudo_prompt`[¶](#sudo-prompt "永久链接至标题")

**Default:** `"sudo password:"`

传递给远程系统的 `sudo` 程序，Fabric 可以通过它正确识别密码输入请求。

### `sudo_user`[¶](#sudo-user "永久链接至标题")

**Default:** `None`

[`sudo`](https://fabric-chs.readthedocs.io/zh-cn/chs/api/core/operations.html#fabric.operations.sudo "fabric.operations.sudo") 的 `user` 参数为 None 时使用的回调值。和 [`settings`](https://fabric-chs.readthedocs.io/zh-cn/chs/api/core/context_managers.html#fabric.context_managers.settings "fabric.context_managers.settings") 一起使用时能起到很大作用。

### `tasks`[¶](#tasks "永久链接至标题")

**Default:** `[]`

由 `fab` 设置，应用于当前执行的所有任务列表。仅用于信息目的。

### `timeout`[¶](#timeout "永久链接至标题")

**Default:** `10`

网络连接超时时间，单位为秒。

1.4 新版功能.

### `user`[¶](#user "永久链接至标题")

**Default:** 用户的默认用户名

SSH 层连接远程服务器时用到的用户名，可以设置为全局，在不显式指定的情况下都会被应用于主机连接字符串。不过，如果显式指定了，它将被临时覆盖为该值——例如，它可以永远是连接时使用的用户。

下面我们使用一个 fabfile 来模拟一下：

from fabric.api import env, run

env.user \= 'implicit\_user'
env.hosts \= \['host1', 'explicit\_user@host2', 'host3'\]

def print\_user():
    with hide('running'):
        run('echo "%(user)s"' % env)

用于：

$ fab print\_user

\[host1\] out: implicit\_user
\[explicit\_user@host2\] out: explicit\_user
\[host3\] out: implicit\_user

Done.
Disconnecting from host1... done.
Disconnecting from host2... done.
Disconnecting from host3... done.

如你所见，在 `host2` 上运行时 `env.user` 被设置为了 `"explicit_user"`，但是之后又重新设置为原来的值（`"implicit_user"`）。

注解

[\`\`](#id1)env.user\`\`的使用有点让人困惑（它同时用于设置 **和** 信息展示目的），因此未来可能会对其进行修改——信息展示可能会另外采取一个新的 env 变量。

### `version`[¶](#version "永久链接至标题")
