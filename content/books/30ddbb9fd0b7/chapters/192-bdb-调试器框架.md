`bdb` 模块处理基本的调试器函数，例如设置中断点或通过调试器来管理执行。

定义了以下异常：

_exception_ bdb.BdbQuit[¶](#bdb.BdbQuit "Link to this definition")

由 [`Bdb`](#bdb.Bdb "bdb.Bdb") 类引发用于退出调试器的异常。

`bdb` 模块还定义了两个类：

_class_ bdb.Breakpoint(_self_, _file_, _line_, _temporary\=False_, _cond\=None_, _funcname\=None_)[¶](#bdb.Breakpoint "Link to this definition")

这个类实现了临时性中断点、忽略计数、禁用与（重新）启用，以及条件设置等。

中断点通过一个名为 [`bpbynumber`](#bdb.Breakpoint.bpbynumber "bdb.Breakpoint.bpbynumber") 的列表基于数字并通过 [`bplist`](#bdb.Breakpoint.bplist "bdb.Breakpoint.bplist") 基于 `(file, line)` 对进行索引。前者指向一个 [`Breakpoint`](#bdb.Breakpoint "bdb.Breakpoint") 类的单独实例。后者指向一个由这种实例组成的列表，因为在每一行中可能存在多个中断点。

当创建一个中断点时，它所关联的 [`文件名`](#bdb.Breakpoint.file "bdb.Breakpoint.file") 应当为规范形式。如果定义了 [`funcname`](#bdb.Breakpoint.funcname "bdb.Breakpoint.funcname")，则当该函数的第一行被执行时将增加一次中断点 [`命中`](#bdb.Breakpoint.hits "bdb.Breakpoint.hits") 次数。 [`有条件的`](#bdb.Breakpoint.cond "bdb.Breakpoint.cond") 中断点将总是会计入 `命中` 次数。

[`Breakpoint`](#bdb.Breakpoint "bdb.Breakpoint") 的实例具有下列方法：

从关联到文件/行的列表中删除此中断点。如果它是该位置上的最后一个中断点，还将删除相应的文件/行条目。

将此中断点标记为启用。

disable()[¶](#bdb.Breakpoint.disable "Link to this definition")

将此中断点标记为禁用。

返回一个带有关于此中断点的所有信息的，格式良好的字符串：

-   中断点编号。
    
-   临时状态（删除或保留）。
    
-   文件/行位置。
    
-   中断条件
    
-   要忽略的次数。
    
-   命中的次数。
    

Added in version 3.2.

_class_ bdb.Bdb(_skip\=None_, _backend\='settrace'_)[¶](#bdb.Bdb "Link to this definition")

[`Bdb`](#bdb.Bdb "bdb.Bdb") 类是作为通用的 Python 调试器基类。

这个类负责追踪工具的细节；所派生的类应当实现用户交互。标准调试器类 ([`pdb.Pdb`](https://docs.python.org/zh-cn/3/library/pdb.html#pdb.Pdb "pdb.Pdb")) 就是一个例子。

如果给出了 _skip_ 参数，它必须是一个包含 glob 风格的模块名称模式的可迭代对象。调试器将不会步进到来自与这些模式相匹配的模块的帧。 一个帧是否会被视为来自特定的模块是由帧的 `__name__` 全局变量来确定的。

_backend_ 参数指定用于 [`Bdb`](#bdb.Bdb "bdb.Bdb") 的后端。它可以是 `'settrace'` 或 `'monitoring'`。 `'settrace'` 使用 [`sys.settrace()`](https://docs.python.org/zh-cn/3/library/sys.html#sys.settrace "sys.settrace")，它具有最佳的向后兼容性。`'monitoring'` 后端使用 Python 3.12 中引入的新的 [`sys.monitoring`](https://docs.python.org/zh-cn/3/library/sys.monitoring.html#module-sys.monitoring "sys.monitoring: Access and control event monitoring") 模块，它可以更高效，因为它可以禁用未使用的事件。 我们正试图为两个后端保留确切的接口，但存在一些差异。我们鼓励调试器开发人员使用 `'monitoring'` 后端来实现更好的性能。

在 3.1 版本发生变更: 增加了 _skip_ 形参。

在 3.14 版本发生变更: 增加了 _backend_ 形参。

trace\_dispatch(_frame_, _event_, _arg_)[¶](#bdb.Bdb.trace_dispatch "Link to this definition")

此函数被安装为被调试帧的追踪函数。它的返回值是新的追踪函数（在大多数情况下就是它自身）。

默认实现会决定如何分派帧，这取决于即将被执行的事件的类型（作为字符串传入）。 _event_ 可以是下列值之一：

-   `"line"`: 一个新的代码行即将被执行。
    
-   `"call"`: 一个函数即将被调用，或者进入了另一个代码块。
    
-   `"return"`: 一个函数或其他代码块即将返回。
    
-   `"exception"`: 一个异常已发生。
    
-   `"c_call"`: A C function is about to be called.
    
-   `"c_return"`: A C function has returned.
    
-   `"c_exception"`: A C function has raised an exception.
    

For the Python events, specialized functions (see below) are called. For the C events, no action is taken.

_arg_ 形参取决于之前的事件。

请参阅 [`sys.settrace()`](https://docs.python.org/zh-cn/3/library/sys.html#sys.settrace "sys.settrace") 的文档了解追踪函数的更多信息。对于代码和帧对象的详情，请参考 [标准类型层级结构](https://docs.python.org/zh-cn/3/reference/datamodel.html#types)。

bdb.checkfuncname(_b_, _frame_)[¶](#bdb.checkfuncname "Link to this definition")

bdb.effective(_file_, _line_, _frame_)[¶](#bdb.effective "Link to this definition")

返回 `(active breakpoint, delete temporary flag)` 或 `(None, None)` 作为目标中断点。

_激活的中断点_ 是 [`bplist`](#bdb.Breakpoint.bplist "bdb.Breakpoint.bplist") 中对应 ([`file`](#bdb.Breakpoint.file "bdb.Breakpoint.file"), [`line`](#bdb.Breakpoint.line "bdb.Breakpoint.line")) (它必须存在) 的第一个 [`已启用的`](#bdb.Breakpoint.enabled "bdb.Breakpoint.enabled") 条目，对应的 [`checkfuncname()`](#bdb.checkfuncname "bdb.checkfuncname") 为真值，并且没有为假值的 [`cond`](#bdb.Breakpoint.cond "bdb.Breakpoint.cond") 或为正值的 [`ignore`](#bdb.Breakpoint.ignore "bdb.Breakpoint.ignore") 计数。 _flag_ 表示临时中断点应当被删除，它仅在 `cond` 无法被求值时 (在此情况下，`ignore` 计数将被忽略) 才会为 `False`。

如果不存在这样的条目，则返回 `(None, None)`。
