## Frequently Asked Questions

Which self-hosted services does Tower support?

Tower Pro supports GitHub Enterprise, Bitbucket Server, GitLab EE/CE, and Azure DevOps Server. These are the four platforms with full repository management and pull request support in Tower.

Tower Pro for Windows supports GitHub Enterprise, Bitbucket Server, GitLab EE/CE, Azure DevOps Server, and Gitea. These are the five platforms with full repository management and pull request support in Tower.

Does my data pass through Tower's servers?

No. Tower communicates directly between your machine and your self-hosted server. Nothing is routed through a third-party relay, so your code, credentials, and API requests never leave your network.

Can I connect multiple self-hosted instances?

Yes. You can add as many server entries as you need — different GitLab instances, a GitHub Enterprise server alongside a Bitbucket Server, or multiple environments like production and staging. Tower keeps credentials per host and lets you switch between them cleanly.

What authentication methods are supported?

Tower supports username/password and personal access token authentication for all supported platforms. OAuth is available for services that offer it. Check your platform's documentation for the recommended token scope.

Is this available on both Mac and Windows?

Yes. Self-hosted repository management is fully available in Tower Pro on both macOS and Windows. Your Pro license covers both platforms.
