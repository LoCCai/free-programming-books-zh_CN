— What? How can code "smell"??  
— Well it doesn't have a nose... but it definitely can stink!

![](https://refactoringguru.cn/images/refactoring/content/catalog/bloaters.png?id=32a44a371122874ebd1e8a2cbb9202b9)

### [Bloaters](https://refactoringguru.cn/refactoring/smells/bloaters)

Bloaters are code, methods and classes that have increased to such gargantuan proportions that they are hard to work with. Usually these smells do not crop up right away, rather they accumulate over time as the program evolves (and especially when nobody makes an effort to eradicate them).

-   [Long Method](https://refactoringguru.cn/smells/long-method)
-   [Large Class](https://refactoringguru.cn/smells/large-class)

-   [Primitive Obsession](https://refactoringguru.cn/smells/primitive-obsession)
-   [Long Parameter List](https://refactoringguru.cn/smells/long-parameter-list)

-   [Data Clumps](https://refactoringguru.cn/smells/data-clumps)

![](https://refactoringguru.cn/images/refactoring/content/catalog/oo-abusers.png?id=dee31050499d8d6b5a2d5b2e84e68cc8)

### [Object-Orientation Abusers](https://refactoringguru.cn/refactoring/smells/oo-abusers)

All these smells are incomplete or incorrect application of object-oriented programming principles.

-   [Alternative Classes with Different Interfaces](https://refactoringguru.cn/smells/alternative-classes-with-different-interfaces)

-   [Refused Bequest](https://refactoringguru.cn/smells/refused-bequest)
-   [Switch Statements](https://refactoringguru.cn/smells/switch-statements)

-   [Temporary Field](https://refactoringguru.cn/smells/temporary-field)

![](https://refactoringguru.cn/images/refactoring/content/catalog/change-preventers.png?id=db5f332e55fd4b993e15c419baf1db41)

### [Change Preventers](https://refactoringguru.cn/refactoring/smells/change-preventers)

These smells mean that if you need to change something in one place in your code, you have to make many changes in other places too. Program development becomes much more complicated and expensive as a result.

-   [Divergent Change](https://refactoringguru.cn/smells/divergent-change)

-   [Parallel Inheritance Hierarchies](https://refactoringguru.cn/smells/parallel-inheritance-hierarchies)

-   [Shotgun Surgery](https://refactoringguru.cn/smells/shotgun-surgery)

![](https://refactoringguru.cn/images/refactoring/content/catalog/dispensables.png?id=b1072dc9efcf8c0374ddbd7e0b8d496f)

### [Dispensables](https://refactoringguru.cn/refactoring/smells/dispensables)

A dispensable is something pointless and unneeded whose absence would make the code cleaner, more efficient and easier to understand.

-   [Comments](https://refactoringguru.cn/smells/comments)
-   [Duplicate Code](https://refactoringguru.cn/smells/duplicate-code)

-   [Data Class](https://refactoringguru.cn/smells/data-class)
-   [Dead Code](https://refactoringguru.cn/smells/dead-code)

-   [Lazy Class](https://refactoringguru.cn/smells/lazy-class)
-   [Speculative Generality](https://refactoringguru.cn/smells/speculative-generality)

### [Couplers](https://refactoringguru.cn/refactoring/smells/couplers)

-   [Incomplete Library Class](https://refactoringguru.cn/smells/incomplete-library-class)
-   [Message Chains](https://refactoringguru.cn/smells/message-chains)
