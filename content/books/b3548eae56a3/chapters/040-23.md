Scrapy使用 [`Request`](#scrapy.http.Request "scrapy.http.Request") 和 [`Response`](#scrapy.http.Response "scrapy.http.Response") 对象爬取web站点。

一般来说，[`Request`](#scrapy.http.Request "scrapy.http.Request") 对象在spiders中被生成并且最终传递到 下载器(Downloader)，下载器对其进行处理并返回一个 [`Response`](#scrapy.http.Response "scrapy.http.Response") 对象， [`Response`](#scrapy.http.Response "scrapy.http.Response") 对象还会返回到生成request的spider中。

所有 [`Request`](#scrapy.http.Request "scrapy.http.Request") and [`Response`](#scrapy.http.Response "scrapy.http.Response") 的子类都会实现一些在基类中非必要的 功能。它们会在 [Request subclasses](#topics-request-response-ref-request-subclasses) 和 [Response subclasses](#topics-request-response-ref-response-subclasses) 两部分进行详细的说明。

### Passing additional data to callback functions[¶](#passing-additional-data-to-callback-functions "永久链接至标题")

The callback of a request is a function that will be called when the response of that request is downloaded. The callback function will be called with the downloaded [`Response`](#scrapy.http.Response "scrapy.http.Response") object as its first argument.

Example:

def parse\_page1(self, response):
    return scrapy.Request("http://www.example.com/some\_page.html",
                          callback\=self.parse\_page2)

def parse\_page2(self, response):
    \# this would log http://www.example.com/some\_page.html
    self.log("Visited %s" % response.url)

In some cases you may be interested in passing arguments to those callback functions so you can receive the arguments later, in the second callback. You can use the [`Request.meta`](#scrapy.http.Request.meta "scrapy.http.Request.meta") attribute for that.

Here’s an example of how to pass an item using this mechanism, to populate different fields from different pages:

def parse\_page1(self, response):
    item \= MyItem()
    item\['main\_url'\] \= response.url
    request \= scrapy.Request("http://www.example.com/some\_page.html",
                             callback\=self.parse\_page2)
    request.meta\['item'\] \= item
    return request

def parse\_page2(self, response):
    item \= response.meta\['item'\]
    item\['other\_url'\] \= response.url
    return item

### FormRequest objects[¶](#formrequest-objects "永久链接至标题")

The FormRequest class extends the base [`Request`](#scrapy.http.Request "scrapy.http.Request") with functionality for dealing with HTML forms. It uses [lxml.html forms](http://lxml.de/lxmlhtml.html#forms) to pre-populate form fields with form data from [`Response`](#scrapy.http.Response "scrapy.http.Response") objects.

_class_ `scrapy.http.``FormRequest`(_url_\[, _formdata_, _..._\])[¶](#scrapy.http.FormRequest "永久链接至目标")

The [`FormRequest`](#scrapy.http.FormRequest "scrapy.http.FormRequest") class adds a new argument to the constructor. The remaining arguments are the same as for the [`Request`](#scrapy.http.Request "scrapy.http.Request") class and are not documented here.

<table><colgroup><col> <col></colgroup><tbody><tr><th>参数:</th><td><strong>formdata</strong> (<em>dict</em><em> or </em><em>iterable of tuples</em>) – is a dictionary (or iterable of (key, value) tuples) containing HTML Form data which will be url-encoded and assigned to the body of the request.</td></tr></tbody></table>

The [`FormRequest`](#scrapy.http.FormRequest "scrapy.http.FormRequest") objects support the following class method in addition to the standard [`Request`](#scrapy.http.Request "scrapy.http.Request") methods:

_classmethod_ `from_response`(_response_\[, _formname=None_, _formnumber=0_, _formdata=None_, _formxpath=None_, _clickdata=None_, _dont\_click=False_, _..._\])[¶](#scrapy.http.FormRequest.from_response "永久链接至目标")

Returns a new [`FormRequest`](#scrapy.http.FormRequest "scrapy.http.FormRequest") object with its form field values pre-populated with those found in the HTML `<form>` element contained in the given response. For an example see [使用FormRequest.from\_response()方法模拟用户登录](#topics-request-response-ref-request-userlogin).

The policy is to automatically simulate a click, by default, on any form control that looks clickable, like a `<input type="submit">`. Even though this is quite convenient, and often the desired behaviour, sometimes it can cause problems which could be hard to debug. For example, when working with forms that are filled and/or submitted using javascript, the default [`from_response()`](#scrapy.http.FormRequest.from_response "scrapy.http.FormRequest.from_response") behaviour may not be the most appropriate. To disable this behaviour you can set the `dont_click` argument to `True`. Also, if you want to change the control clicked (instead of disabling it) you can also use the `clickdata` argument.

<table><colgroup><col> <col></colgroup><tbody><tr><th>参数:</th><td><ul><li><strong>response</strong> (<a href="#scrapy.http.Response" title="scrapy.http.Response"><code><span>Response</span></code></a> object) – the response containing a HTML form which will be used to pre-populate the form fields</li><li><strong>formname</strong> (<em>string</em>) – if given, the form with name attribute set to this value will be used.</li><li><strong>formxpath</strong> (<em>string</em>) – if given, the first form that matches the xpath will be used.</li><li><strong>formnumber</strong> (<em>integer</em>) – the number of form to use, when the response contains multiple forms. The first one (and also the default) is <code><span>0</span></code>.</li><li><strong>formdata</strong> (<em>dict</em>) – fields to override in the form data. If it’s not given, the form data will be submitted simulating a click on the first clickable element. In addition to html attributes, the control can be identified by its zero-based index relative to other submittable inputs inside the form, via the <code><span>nr</span></code> attribute.</li><li><strong>dont_click</strong> (<em>boolean</em>) – If True, the form data will be submitted without clicking in any element.</li></ul></td></tr></tbody></table>

The other parameters of this class method are passed directly to the [`FormRequest`](#scrapy.http.FormRequest "scrapy.http.FormRequest") constructor.

### Request usage examples[¶](#request-usage-examples "永久链接至标题")

#### Using FormRequest to send data via HTTP POST[¶](#using-formrequest-to-send-data-via-http-post "永久链接至标题")

If you want to simulate a HTML Form POST in your spider and send a couple of key-value fields, you can return a [`FormRequest`](#scrapy.http.FormRequest "scrapy.http.FormRequest") object (from your spider) like this:

return \[FormRequest(url\="http://www.example.com/post/action",
                    formdata\={'name': 'John Doe', 'age': '27'},
                    callback\=self.after\_post)\]

#### 使用FormRequest.from\_response()方法模拟用户登录[¶](#formrequest-from-response "永久链接至标题")

通常网站通过 `<input type="hidden">` 实现对某些表单字段（如数据或是登录界面中的认证令牌等）的预填充。 使用Scrapy抓取网页时，如果想要预填充或重写像用户名、用户密码这些表单字段， 可以使用 [`FormRequest.from_response()`](#scrapy.http.FormRequest.from_response "scrapy.http.FormRequest.from_response") 方法实现。下面是使用这种方法的爬虫例子:

import scrapy

class LoginSpider(scrapy.Spider):
    name \= 'example.com'
    start\_urls \= \['http://www.example.com/users/login.php'\]

    def parse(self, response):
        return scrapy.FormRequest.from\_response(
            response,
            formdata\={'username': 'john', 'password': 'secret'},
            callback\=self.after\_login
        )

    def after\_login(self, response):
        \# check login succeed before going on
        if "authentication failed" in response.body:
            self.log("Login failed", level\=log.ERROR)
            return

        \# continue scraping with authenticated session...

[`TextResponse`](#scrapy.http.TextResponse "scrapy.http.TextResponse") objects adds encoding capabilities to the base [`Response`](#scrapy.http.Response "scrapy.http.Response") class, which is meant to be used only for binary data, such as images, sounds or any media file.

[`TextResponse`](#scrapy.http.TextResponse "scrapy.http.TextResponse") objects support the following attributes in addition to the standard [`Response`](#scrapy.http.Response "scrapy.http.Response") ones:

`encoding`[¶](#scrapy.http.TextResponse.encoding "永久链接至目标")

A string with the encoding of this response. The encoding is resolved by trying the following mechanisms, in order:

1.  the encoding passed in the constructor encoding argument
2.  the encoding declared in the Content-Type HTTP header. If this encoding is not valid (ie. unknown), it is ignored and the next resolution mechanism is tried.
3.  the encoding declared in the response body. The TextResponse class doesn’t provide any special functionality for this. However, the [`HtmlResponse`](#scrapy.http.HtmlResponse "scrapy.http.HtmlResponse") and [`XmlResponse`](#scrapy.http.XmlResponse "scrapy.http.XmlResponse") classes do.
4.  the encoding inferred by looking at the response body. This is the more fragile method but also the last one tried.

`selector`[¶](#scrapy.http.TextResponse.selector "永久链接至目标")

A [`Selector`](https://scrapy-chs.readthedocs.io/zh_CN/latest/topics/selectors.html#scrapy.selector.Selector "scrapy.selector.Selector") instance using the response as target. The selector is lazily instantiated on first access.

[`TextResponse`](#scrapy.http.TextResponse "scrapy.http.TextResponse") objects support the following methods in addition to the standard [`Response`](#scrapy.http.Response "scrapy.http.Response") ones:

`body_as_unicode`()[¶](#scrapy.http.TextResponse.body_as_unicode "永久链接至目标")

Returns the body of the response as unicode. This is equivalent to:

response.body.decode(response.encoding)

But **not** equivalent to:

unicode(response.body)

Since, in the latter case, you would be using you system default encoding (typically ascii) to convert the body to unicode, instead of the response encoding.
