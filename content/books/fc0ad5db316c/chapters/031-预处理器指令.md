虽然编译器没有单独的预处理器，但它处理本部分中所述的指令，就好像有一个指令一样。 使用这些指令来帮助进行条件编译。 不同于 C 和 C++ 指令，不能使用这些指令来创建宏。 预处理器指令必须是一行中唯一的说明。

C# 语言参考记录了最近发布的 C# 语言版本。 它还包含即将发布的语言版本公共预览版中功能的初始文档。

本文档标识了在语言的最后三个版本或当前公共预览版中首次引入的任何功能。

## 基于文件的应用

_基于文件的应用_ 是使用 `dotnet run Program.cs` （或任何 `*.cs` 文件）编译和运行的程序。 C# 编译器忽略这些预处理器指令，但生成系统对其进行分析以生成输出。 在基于项目的编译中遇到这些指令时，这些指令将生成警告。

C# 编译器忽略以 `#:` 或 `#!`. 开头的任何预处理器指令。

`#!`预处理器指令使 Unix 操作系统能够使用其文件名直接执行 C# 文件。

```
#!/usr/bin/env dotnet
Console.WriteLine("Hello");
```

文件中的第一行通知 Unix 操作系统使用 `dotnet`. 该 `/usr/bin/env` 命令在 PATH 中定位 `dotnet` 可执行文件，使此方法可移植到不同 Unix 和 macOS 分发版中，这些 `dotnet` 分发版可能安装在不同的位置。 除了在 C# 文件中包括此行外，还需要设置 _执行_ （`x`） 权限 （`chmod +x <file>`）。

`#:`基于文件的应用中使用的指令在[基于文件的应用引用](https://learn.microsoft.com/zh-cn/dotnet/core/sdk/file-based-apps)中介绍。

其他工具可以按照 `#:` 约定添加新令牌。

## 可为空上下文

设置 `#nullable` 预处理器指令 _注释_ 和 _警告_ 中的标记 _可空上下文_. 此指令控制是否可为空注释是否有效，以及是否给出为 Null 性警告。 每个标志要么 _禁用_，要么 _启用_。

可以通过将元素添加到[`Nullable`](https://learn.microsoft.com/zh-cn/dotnet/csharp/language-reference/compiler-options/language#nullable)元素，在项目级别（C# 源代码外部）指定这`PropertyGroup`两个上下文。 `#nullable` 指令控制批注和警告标志，并优先于项目级设置。 一条指令会设置它所控制的标志，直到另一条指令覆盖它，或直到源文件结束。

指令的效果如下所示：

-   `#nullable disable`: 设置可空上下文 _禁用_.
-   `#nullable enable`: 设置可空上下文 _启用_.
-   `#nullable restore`: 将可空上下文恢复为项目设置。
-   `#nullable disable annotations`: 将 nullable 上下文中的注释标志设置为 _残_.
-   `#nullable enable annotations`: 将 nullable 上下文中的注释标志设置为 _启用_.
-   `#nullable restore annotations`: 将可空上下文中的注释标志恢复为项目设置。
-   `#nullable disable warnings`: 将可空上下文中的警告标志设置为 _残_.
-   `#nullable enable warnings`: 将可空上下文中的警告标志设置为 _启用_.
-   `#nullable restore warnings`: 将可空上下文中的警告标志恢复为项目设置。

## 条件编译

仅在定义指定的符号时或者在使用 `#if` not 运算符时未定义指定的符号时，C# 编译器才编译 `#endif` 指令和 `!` 指令之间的代码。 与 C 和 C++ 不同，无法向符号分配数值。 C# 中的 `#if` 语句为布尔值，仅测试是否定义符号。 例如，定义 `DEBUG` 时将编译以下代码：

```
#if DEBUG
    Console.WriteLine("Debug version");
#endif
```

未定义 `MYTEST` 时，将编译以下代码：

```
#if !MYTEST
    Console.WriteLine("MYTEST is not defined");
#endif
```

使用运算符 [`==` （相等）](https://learn.microsoft.com/zh-cn/dotnet/csharp/language-reference/operators/equality-operators#equality-operator-) 和 [`!=` （不相等）](https://learn.microsoft.com/zh-cn/dotnet/csharp/language-reference/operators/equality-operators#inequality-operator-) 测试 [`bool`](https://learn.microsoft.com/zh-cn/dotnet/csharp/language-reference/builtin-types/bool) 值 `true` 或 `false`。 `true` 表示定义该符号。 语句 `#if DEBUG` 具有与 `#if (DEBUG == true)` 相同的含义。 [`&&` 使用 （和）](https://learn.microsoft.com/zh-cn/dotnet/csharp/language-reference/operators/boolean-logical-operators#conditional-logical-and-operator-)、 [`||` （或）](https://learn.microsoft.com/zh-cn/dotnet/csharp/language-reference/operators/boolean-logical-operators#conditional-logical-or-operator-) 和 [`!` （或）](https://learn.microsoft.com/zh-cn/dotnet/csharp/language-reference/operators/boolean-logical-operators#logical-negation-operator-) 运算符来评估是否定义了多个符号。 还可以用括号对符号和运算符进行分组。

以下示例演示了一个复杂指令，该指令允许代码利用较新的 .NET 功能，同时保持向后兼容。 例如，假设你在代码中使用 NuGet 包，但该包仅支持 .NET 6（及更高版本）和 .NET Standard 2.0（及更高版本）：

```
#if (NET6_0_OR_GREATER || NETSTANDARD2_0_OR_GREATER)
    Console.WriteLine("Using .NET 6+ or .NET Standard 2+ code.");
#else
    Console.WriteLine("Using older code that doesn't support the above .NET versions.");
#endif
```

`#if` 以及 `#else`、`#elif`、`#endif`、`#define` 和 `#undef` 指令，允许基于是否存在一个或多个符号包括或排除代码。 条件编译在编译调试版本的代码或编译特定配置的代码时会很有用。

`#elif` 可以创建复合条件指令。 如果前面的表达式和任何前面的`#elif`（可选）`#if`指令表达式的计算结果都不是，编译器将计算`#elif`表达式`true`。 如果 `#elif` 表达式计算结果为 `true`，编译器将计算 `#elif` 和下一条件指令间的所有代码。 例如：

```
#define VC7
//...
#if DEBUG
    Console.WriteLine("Debug build");
#elif VC7
    Console.WriteLine("Visual Studio 7");
#endif
```

`#else` 可以创建复合条件指令。 如果上述`#if`或（可选）`#elif`指令中没有任何表达式的计算结果`true`，编译器将计算下一个和下一个`#else`指令之间的`#endif`所有代码。 `#endif` 必须是后面的 `#else`下一个预处理器指令。

`#endif` 指定条件指令的末尾，以 `#if` 指令开头。

下面的示例演示如何在文件中定义`MYTEST`符号，然后测试符号和`MYTEST`符号的值`DEBUG`。 此示例的输出取决于是在 **调试** 模式还是 **发布** 配置模式下生成项目。

```
#define MYTEST
using System;
public class MyClass
{
    static void Main()
    {
#if (DEBUG && !MYTEST)
        Console.WriteLine("DEBUG is defined");
#elif (!DEBUG && MYTEST)
        Console.WriteLine("MYTEST is defined");
#elif (DEBUG && MYTEST)
        Console.WriteLine("DEBUG and MYTEST are defined");
#else
        Console.WriteLine("DEBUG and MYTEST are not defined");
#endif
    }
}
```

以下示例演示如何测试不同的目标框架，以便尽可能使用较新的 API：

```
public class MyClass
{
    static void Main()
    {
#if NET40
        WebClient _client = new WebClient();
#else
        HttpClient _client = new HttpClient();
#endif
    }
    //...
}
```

## 定义符号

使用以下两个预处理器指令定义或取消定义条件编译的符号：

-   `#define`：定义符号。
-   `#undef`：取消定义符号。

用于 `#define` 定义符号。 使用符号作为传递给 `#if` 指令的表达式时，表达式的计算结果为 `true`，如以下示例所示：

```
#define VERBOSE

#if VERBOSE
   Console.WriteLine("Verbose output version");
#endif
```

注意

在 C# 中，应使用 [`const`](https://learn.microsoft.com/zh-cn/dotnet/csharp/language-reference/keywords/const) 关键字定义基元常量。 `const` 声明会创建一个在运行时无法修改的 `static` 成员。 `#define` 指令不能用于声明常量值，这与 C 和 C++ 中的通常做法一样。 如果具有多个此类常量，请考虑创建一个单独的“常量”类来容纳它们。

使用符号指定编译条件。 使用或 `#if``#elif`.. 测试符号。 还可以使用 [ConditionalAttribute](https://learn.microsoft.com/zh-cn/dotnet/api/system.diagnostics.conditionalattribute) 来执行条件编译。 可以定义符号，但不能为符号分配值。 文件中必须先出现 `#define` 指令，才能使用并非同时也是预处理器指令的任何指示。 还可以使用 [**DefineConstants**](https://learn.microsoft.com/zh-cn/dotnet/csharp/language-reference/compiler-options/language#defineconstants) 编译器选项定义符号。 使用 `#undef`. 取消定义符号。

## 定义区域

使用以下两个预处理器指令定义可在大纲中折叠的代码区域：

-   `#region`：开始区域。
-   `#endregion`：结束区域。

利用 `#region`，可以指定在使用代码编辑器的[大纲](https://learn.microsoft.com/zh-cn/visualstudio/ide/outlining)功能时可展开或折叠的代码块。 在较长的代码文件中，折叠或隐藏一个或多个区域十分便利，这样，可将精力集中于当前处理的文件部分。 下面的示例演示如何定义区域：

```
#region MyClass definition
public class MyClass
{
    static void Main()
    {
    }
}
#endregion
```

`#region` 块必须通过 `#endregion` 指令终止。 `#region` 块不能与 `#if` 块重叠。 但是，可以将 `#region` 块嵌套在 `#if` 块内，或将 `#if` 块嵌套在 `#region` 块内。

## 错误和警告信息

可以使用以下指令生成用户定义的编译器错误和警告，以及控制行信息：

-   `#error`：使用指定的消息生成编译器错误。
-   `#warning`：使用指定的消息生成编译器警告。
-   `#line`：更改用编译器消息输出的行号。

用于 `#error` 从代码中的特定位置生成 [CS1029](https://learn.microsoft.com/zh-cn/dotnet/csharp/language-reference/compiler-messages/preprocessor-errors) 用户定义的错误。 例如：

```
#error Deprecated code in this method.
```

注意

编译器以特殊的方式处理 `#error version` 并报告编译器错误 CS8304，消息中包含使用的编译器和语言版本。

用于 `#warning` 从代码中的特定位置生成 [CS1030](https://learn.microsoft.com/zh-cn/dotnet/csharp/language-reference/compiler-messages/preprocessor-errors) 级别一级编译器警告。 例如：

```
#warning Deprecated code in this method.
```

用于 `#line` 修改编译器的行号和（可选）错误和警告的文件名输出。

以下示例演示如何报告与行号相关联的两个警告。 该 `#line 200` 指令强制下一行的数字为 200（尽管默认值为 #6），直到下一 `#line` 个指令为止，文件名将报告为“Special”。该 `#line default` 指令将行号返回到其默认编号，这将计算上一指令重新编号的行数。

```
class MainClass
{
    static void Main()
    {
#line 200 "Special"
        int i;
        int j;
#line default
        char c;
        float f;
#line hidden // numbering not affected
        string s;
        double d;
    }
}
```

编译产生以下输出：

```
Special(200,13): warning CS0168: The variable 'i' is declared but never used
Special(201,13): warning CS0168: The variable 'j' is declared but never used
MainClass.cs(9,14): warning CS0168: The variable 'c' is declared but never used
MainClass.cs(10,15): warning CS0168: The variable 'f' is declared but never used
MainClass.cs(12,16): warning CS0168: The variable 's' is declared but never used
MainClass.cs(13,16): warning CS0168: The variable 'd' is declared but never used
```

可在生成过程的自动、中间步骤中使用 `#line` 指令。 例如，如果从原始源代码文件中删除行，但仍希望编译器根据文件中的原始行号生成输出，则可以删除行，然后通过使用 `#line`模拟原始行号。

该 `#line hidden` 指令隐藏调试器中的连续行，这样，当开发人员逐步执行代码时，将逐行执行 a `#line hidden` 和下一 `#line` 指令之间的任何行（假设它不是另一个 `#line hidden` 指令）。 还可通过此选项允许 ASP.NET 区分用户定义和计算机生成的代码。 尽管 ASP.NET 是此功能的主要使用者，但可能有更多的源生成器使用它。

`#line hidden` 指令不影响错误报告中的文件名或行号。 也就是说，如果编译器在隐藏块中找到错误，编译器将报告错误的当前文件名和行号。

`#line filename` 指令可指定要在编译器输出中显示的文件名。 默认情况下，将使用源代码文件的实际名称。 文件名必须采用双引号（“”），并且必须遵循行号。

可以使用一种新的 `#line` 指令形式：

```
#line (1, 1) - (5, 60) 10 "partial-class.cs"
/*34567*/int b = 0;
```

这种形式的组件包括：

-   `(1, 1)`: 指令后一行第一个字符的起始行和列。 在此示例中，下一行报告为第 1 行，第 1 列 1。
-   `(5, 60)`：标记区域的结束行和列。
-   `10`：将使 `#line` 指令生效的列偏移量。 在此示例中，第 10 列报告为第一列。 声明 `int b = 0;` 从这一列开始。 此字段可选。 如果省略了该字段，则指令将对第 1 列生效。
-   `"partial-class.cs"`：输出文件的名称。

前面的示例生成以下警告：

```
partial-class.cs(1,5,1,6): warning CS0219: The variable 'b' is assigned but its value is never used
```

重新映射后，变量 `b` 位于文件 `partial-class.cs`的第一行（第六个字符）。

特定于域的语言 (DSL) 通常使用此格式来提供从源文件到生成的 C# 输出的更好的映射。 此扩展 `#line` 指令的最常见用途是将生成的文件中出现的警告或错误重新映射到原始源。 例如，请考虑以下 razor 页：

```
@page "/"
Time: @DateTime.NowAndThen
```

该属性 `DateTime.Now` 的类型不正确 `DateTime.NowAndThen`。 在 `page.g.cs` 中，为此 razor 代码片段生成的 C# 如下所示：

```
  _builder.Add("Time: ");
#line (2, 6) - (2, 27) 15 "page.razor"
  _builder.Add(DateTime.NowAndThen);
```

前面的代码片段的编译器输出如下：

```
page.razor(2, 2, 2, 27)error CS0117: 'DateTime' does not contain a definition for 'NowAndThen'
```

第 2 行第 6 栏 `page.razor` 是文本 `@DateTime.NowAndThen` 开始，由 `(2, 6)` 在指令中。 该跨度 `@DateTime.NowAndThen` 在第 2 行第 27 栏结束，由 `(2, 27)` 在指令中。 文本为 `DateTime.NowAndThen` 的第 15 栏开始。`page.g.cs`, 注意到 `15` 在指令中。 编译器会将错误报告在 `page.razor`. 开发人员可直接导航到该错误在源代码（而不是生成的源）中的位置。

若要查看此格式的更多示例，请参阅 C# 规范中的 [Line 指令](https://learn.microsoft.com/zh-cn/dotnet/csharp/language-reference/language-specification/lexical-structure#658-line-directives) 。

## Pragma

编译器用于 `#pragma` 获取用于编译其显示位置的文件的特殊说明。 编译器必须支持您使用的实用程序。 换句话说，不能使用 `#pragma` 创建自定义的预处理指令。

-   [`#pragma warning`](#pragma-warning)：启用或禁用警告。
-   [`#pragma checksum`](#pragma-checksum)：生成校验和。

```
#pragma pragma-name pragma-arguments
```

`pragma-name` 是已识别杂注的名称。 `pragma-arguments` 是特定于杂注的参数。

### #pragma 警告

`#pragma warning` 可以启用或禁用特定警告。 `#pragma warning disable format` 和 `#pragma warning enable format` 控制 Visual Studio 如何设置代码块的格式。

```
#pragma warning disable warning-list
#pragma warning restore warning-list
```

`warning-list` 是警告编号的逗号分隔列表，例如 `414, CS3021`。 “CS”前缀是可选的。 如果未指定警告编号， `disable` 则禁用所有警告并 `restore` 启用所有警告。

注意

若要在 Visual Studio 中查找警告编号，请生成项目，然后在“输出”窗口中查找警告编号。

`disable` 从源文件的下一行开始生效。 警告会在后面的 `restore` 行上还原。 如果文件中没有 `restore` ，则警告将还原到同一编译中任何后续文件的第一行的默认状态。

```
// pragma_warning.cs
using System;

#pragma warning disable 414, CS3021
[CLSCompliant(false)]
public class C
{
    int i = 1;
    static void Main()
    {
    }
}
#pragma warning restore CS3021
[CLSCompliant(false)]  // CS3021
public class D
{
    int i = 1;
    public static void F()
    {
    }
}
```

的另一种形式 `warning` pragma 在代码块中禁用或恢复 Visual Studio 格式化命令：

```
#pragma warning disable format
#pragma warning restore format
```

Visual Studio 格式命令不会在 `disable format` 生效的代码块中修改文本。 格式命令（如 Ctrl+K、Ctrl+D）不会修改这些代码区域。 通过该实用程序 您可以对代码的可视化表达方式进行精细控制。

### #pragma 校验和

为源文件生成校验和，以帮助调试 ASP.NET 页面。

```
#pragma checksum "filename" "{guid}" "checksum bytes"
```

该指令用作 `"filename"` 文件的名称来监视更改或更新， `"{guid}"` 作为哈希算法的全局唯一标识符（GUID），以及 `"checksum_bytes"` 表示校验和字节的十六进制数字字符串。 必须提供偶数十六进制数字。 奇数个数字会导致编译时警告出现，且指令遭忽略。

Visual Studio 调试器使用校验和确保它可始终找到正确的源。 编译器为源文件计算校验和，然后将输出发出到程序数据库 (PDB) 文件。 调试器使用 PDB 与它为源文件计算的校验和进行比较。

此解决方案不适用于 ASP.NET 项目，因为计算出的校验和是针对生成的源文件，而不是 .aspx 文件。 为解决此问题，`#pragma checksum` 为 ASP.NET 页面提供校验和支持。

在 Visual C# 中创建 ASP.NET 项目时，生成的源文件包含 .aspx 文件（从该文件生成源）的校验和。 编译器随后将此信息写入 PDB 文件中。

如果编译器在文件中没有找到 `#pragma checksum` 指令，它将计算校验和，并将该值写入 PDB 文件。

```
class TestClass
{
    static int Main()
    {
        #pragma checksum "file.cs" "{406EA660-64CF-4C82-B6F0-42D48172A799}" "ab007f1d23d9" // New checksum
    }
}
```
